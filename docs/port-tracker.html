Phases

Each phase is done when its unit tests pass, its parity checks pass, and the command table flips those commands to native. Numbering is the real build order: every phase depends only on crates finished before it.

Rules the port follows

  • Never go dark. Any command without a Rust implementation runs the Python one. Same flags, same exit code, same output. XIL_FORCE_PY=all forces Python for A/B runs.
  • ffmpeg does every codec job. pydub decodes through ffmpeg, so Rust decoding through the same ffmpeg keeps the samples identical. Rust only does the PCM math.
  • Copy pydub's math, do not improve it. Gain truncates toward zero and saturates to 16-bit. Fades above 100 ms step once per millisecond. Pan uses pydub's own formula.
  • The ML workers stay Python. Chatterbox, Whisper and MMAudio keep their venvs. Rust is only their JSON-over-stdio client.
  • Parity before flip. A command flips to native only when its entry in tools/parity/suite.toml is green in CI.
  • Text is byte-identical. JSON (key order and float formatting included), CSV, Audacity labels, timeline HTML, log messages.
  • Audio has limits, not equality. Length within ±1 ms · RMS within 0.1 dB · peak within 0.2 dB · 1 s envelope correlation above 0.999. DAW layer WAVs must still be byte-identical.
  • Build on ext4. Source may live on /mnt/c; object files go to ~/.cargo-target/rxil.

Docs

Two tools, split by audience, so the toolchain stays all-Rust and nothing is hand-maintained twice.

  • rustdoc, from phase 0 on. Every crate's API reference, generated straight from /// comments. CI runs it strict — cargo doc --workspace --no-deps --document-private-items with RUSTDOCFLAGS=-D warnings — the Rust-side twin of the Python repo's mkdocs strict: true gate. A broken doc link fails the merge, same as a broken test.
  • Placeholders in --help text are not doc bugs. clap derive doc comments are the --help output, copied verbatim from argparse so parity can diff it byte for byte. Rustdoc reads <slug>-style placeholders as HTML; xil-cli/src/cmd/mod.rs silences that one lint instead of adding backticks that would change the help text.
  • mdBook, deferred to phase 7. Replaces the Python repo's ~38 hand-written mkdocs pages (about, configuration, cues, guides, internals, samples) once the shim is gone. Starting it earlier would mean two user guides describing one command table while most of it still delegates to Python — a confusing split for no benefit yet.
  • Until then, the Python docs are the user guide. The Read the Docs site (mkdocs + mkdocstrings) stays the single reference for anyone using xil day to day; this page tracks the Rust build, not end-user docs.

Known risks

  • pydub arithmetic. One wrong rounding rule and every WAV differs by a bit. Mitigation: each primitive op gets a byte-identical WAV test against recorded pydub output before any stage uses it.
  • JSON formatting. Python writes 1e-05, Rust writes 1e-5; some files escape non-ASCII, some do not. Mitigation: a custom serializer with a per-file ascii switch taken from the Python source.
  • difflib ratios. The scanner's 0.72 near-miss cutoff is a behaviour boundary. Mitigation: hand-rolled Ratcliff/Obershelp tested against a table of ratios recorded from Python.
  • Slow builds on drvfs. Mitigation in place: target dir on ext4. Fallback: move the source to ~/src and symlink.
  • A broken Python venv breaks every delegated command. Mitigation in place: xil status --toolchain shows which Python is resolved.
